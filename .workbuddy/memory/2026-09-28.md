# 2026-09-28

## 日程订阅（iCalendar）技术调研

- 调研对象 `https://pro.hori.cloud/share/calendarics/v1`：ThinkPHP V5.1 + nginx 动态渲染的 RFC 5545 订阅源，
  438 个全天 VEVENT，120KB / 4200 行，CRLF + 75 octet 折叠，`DTSTAMP` 随请求时刻变 → 每次实时渲染。
  路径 `v1`/`v2` 是日历通道标识（v2 返回 200 但空 body），**无任何鉴权**。
- 实测抓包结论已写入 `docs/calendar-subscription-plan.md`（含对方 9 个实现问题对照表）。
- 对方主要缺陷：`Content-Type: text/html`（应为 text/calendar）、无 `X-WR-CALNAME`、无 `REFRESH-INTERVAL`/`X-PUBLISHED-TTL`、
  无 `SEQUENCE`/`LAST-MODIFIED`/`STATUS`（无法更新与取消）、滥用 `ATTENDEE`、无缓存头、无鉴权导致客户名全公开。
- 对方做得对的点：UID 用业务主键（`HMG_PRJ_202201001`）、全天事件 `VALUE=DATE` + 排他 `DTEND`（+1 天）、
  `METHOD:PUBLISH`、状态编码进 SUMMARY。

## 最小方案 v1 定稿（已追加为文档「附 B」，未写代码）

- 用户倾向：先做与对方同等水平（全天事件、单条公开链接），**鉴权/加密/token 本轮全不做**。
- 实测数据（2026-09-28 拉 /api/activities）：**196 条**（非文档所载 184）；日期填充 100%、格式统一 YYYY-MM-DD；
  区间 2018-09-15~2026-09-25，**无任何未来活动**；地点填充仅 82/196（114 条空）；
  类型分布：校园新闻采编制作 92 · 发展建设 39 · 数媒实践 34 · 宣传 18 · 影视 13；
  近两年（2025+2026 共 87 条）中「校园新闻采编制作」占 39 条（45%，多为拍摄/期刊任务，是日历噪音大头）。
- 决策 1 结束日期：**加列 + 兜底**。飞书加「活动结束日期」（日期型，可空），代码 `end = endDate || date`，
  DTEND = end+1。约 5% 长周期活动（常驻征集、上半年综合项目、Filmarathon）需要，其余留空即单日。
- 决策 2 公开控制：**加「隐藏日程」反向复选框**（不叫「是否公开日程」）。代码 `if (f["隐藏日程"] === true) continue`。
  理由：正向列需批量勾 196 条且新增漏勾=静默不进日历；飞书复选框空值 undefined/false 有歧义，反向判定无歧义、开箱即用。
- 决策 3 时间窗口：默认「近 1 年 + 全部未来」，`?from=YYYY` / `?all=1` 可覆盖（全量 196 条会变档案库）。
- 兜底三处：结束日期空→单日；地点空→不输出 LOCATION（不写"待定"）；无开始时间→全天 VALUE=DATE。
- 本轮不做：token/加密/个人订阅、开始时间列、VALARM、STATUS 取消语义、SEQUENCE/LAST-MODIFIED。
- **最重要的非技术点**：196 条全是事后录入，无未来活动 → 订阅后日历只有过去。要让日历有用，
  社团必须在活动发生前录入并填未来日期（运营要求，代码无法解决）。
