✓POST /api/checkin实时 · 双写
  • body：uid, mode(qr|nfc), activity, duration, lat, lng, name
  • 服务端按 uid 实时重查（findMemberByUid 直连飞书，不信任前端成员信息）
  • ctx.waitUntil 异步：飞书机器人卡片 + WPS 写入，失败互不影响
  • 查无成员时用前端 name 兜底（新卡登记）；签到秒回 {ok:true}

  • 鉴权：Authorization: Bearer 或 ?token=（REFRESH_TOKEN）
  • 冷却：KV last_refresh_at 30s → 429（跨实例一致）
  • force 重建 4 个快照：members_full + activity_records_v3 + activity_projects_v1 + file_catalog_v1
  • 供飞书自动化「记录变更 → HTTP」调用（即时刷新）
  • 案例 → §3-12
✓定时任务 scheduled()
  • Cron 30 * * * *（每小时第 30 分，wrangler.jsonc）
  • 四段独立 try：members → activity_records_v3 → activity_projects_v1 → file_catalog_v1(force)
  • 单段失败不影响其余（各自 catch 打日志）
  • 兜底：即使无人触发，数据陈旧 ≤ 1 小时
